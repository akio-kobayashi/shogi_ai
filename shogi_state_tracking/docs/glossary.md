# 用語集

4つの文書とCSVに出てくる用語をまとめたページです。各文書では、用語が最初に出てくる箇所からこのページへリンクしています。

列名はCSVでの名前です。`by_run.csv` の元の列名は [CSVの作られ方と、各列の計算内容](csv_computation.md) の第3節にあります。

## 将棋と棋譜

| 用語 | 意味 |
|---|---|
| 手（ply）、手数 | 先手・後手のどちらかが1回指すことを1手と数えます。手数は対局の初めから数えた手の番号です |
| 指手 | 1手で行う操作。通常の移動、成り、駒打ちの3種類があります |
| 通常の移動 | 盤上の駒を別のマスへ動かす指手。成りを伴わないもの |
| 成り | 駒を動かすと同時に裏返し、動き方を変える指手 |
| 駒打ち | 持ち駒を盤上の空いたマスに置く指手。チェスにはない操作です |
| 持ち駒 | 相手から取って手元にある駒。盤上に座標を持たないので、過去にどの駒を取りどの駒を打ったかをたどらないと分かりません |
| 手番 | 次に指すのが先手か後手か。平手初期局面から始めるので、手数の偶奇で決まります |
| 局面 | ある時点の盤面（81マスの駒の配置）、持ち駒、手番をまとめたもの |
| 平手初期局面 | 駒落ちのない、通常の対局の開始局面。この研究の棋譜はすべてここから始まります |
| 合法手 | 将棋の規則で指すことが許される指手 |
| 棋譜 | 1局の指手を順に並べた記録 |
| Floodgate | コンピュータ将棋どうしが対局するサーバー。学習・検証・評価の棋譜はここから取っています |
| Lishogi | オンライン将棋サイト。学習に使っていない外部の棋譜として、BOTでない利用者どうしの対局を使っています |

## モデルと入力

| 用語 | 意味 |
|---|---|
| トークン | モデルが扱う最小単位。座標1つ、駒の種類1つなどが1トークンです。1手は2〜3トークンになります |
| 語彙 | モデルが扱うトークンの種類の一覧。実装上は125語で、この研究で実際に現れるのは101語です |
| `<BOS>` `<MOVES>` `<EOS>` | 系列の始まり、指手の列の始まり、対局の終わりを表すトークン |
| `<DROP>` `<PROMOTE>` | 駒打ちの始まりと、成りを表すトークン |
| Transformer | この研究で使うモデルの種類。入力の各位置について、過去の位置の情報を注意で参照しながら計算を重ねます |
| 層 | モデルの計算の1段。このモデルは12層で、数字が大きいほど出力に近い段です。入力をそのまま表したものを入力の層と呼びます |
| 隠れ状態 | モデルが計算の途中で、各位置・各層に持っている数値の並び（768個） |
| 注意（attention） | 過去のどの位置の情報をどれだけ参照するかを決める仕組み |
| 注意ヘッド | 注意の仕組みを構成する小さな部品。各層に12個あります |
| 因果マスク | 各位置が未来の位置を参照できないようにする仕組み。これにより、途中までの入力で計算した値と、全体を入力して計算した値が一致します |
| 接頭辞 | 系列の先頭からある位置までの部分 |
| シード | 学習を始めるときの乱数の初期値。同じ条件でもシードが違えば結果が少し変わります。この研究では20260802、20260803、20260804の3つです |

## 実験条件

| 用語 | 意味 |
|---|---|
| RAP | 学習のときだけ、通常の移動の直前に、動かす駒の種類のトークンを確率 q で挿入する方法。評価のときは挿入しません |
| q（挿入率） | RAPで駒の種類を挿入する確率。0（RAPなし）、0.15、0.25の3条件と、APの1.0を比べます |
| RAPなし | q=0の条件。指手の並びだけで学習します |
| AP | すべての通常の移動に駒の種類を挿入し、評価のときも正解の駒の種類を与える条件。次の手が駒打ちでないことまで分かってしまうので、他の条件と同じ土俵ではありません。参考値として扱います |
| 主3条件 | RAPなし、q=0.15、q=0.25の3条件。条件の比較はこの3つで行います |
| AP正準指手パープレキシティ | APの指手パープレキシティを、駒の種類のトークンを含めた指手全体で計算した値。他の条件と並べられるのはこちらです |
| 駒種条件付き指手パープレキシティ | APで、正解の駒の種類を与えた後の座標だけを採点した値。他の条件とは比べられません |
| AP診断_ | 学生用CSVで、APだけに出る列の接頭辞。他の条件と比べられない値を入れています |

## 評価のしかた

| 用語 | 意味 |
|---|---|
| 学習集合、検証集合、評価集合 | モデルの学習に使う棋譜、学習の調整に使う棋譜、成績を測る棋譜。対局の期間が重ならないように分けています |
| 抜き出し評価 | 各対局の8手目と32手目の局面だけを使う評価。計算量を減らすための方法で、対局全体の平均ではありません。指手の予測、プローブ、Lishogiはこの方法です |
| 全指手評価 | 評価集合の全720,516手を使う評価。列名が `fh_` で始まります |
| 教師強制 | 正解の途中までをモデルに与えて、次の1トークンだけを当てさせる評価の方法。全指手評価はこの方法です |
| ビーム探索 | 候補を上位いくつか（この研究では5つ）残しながら、1トークンずつ指手を組み立てる方法。将棋の指手として形がおかしいトークンは選べないようにしていますが、合法かどうかは制限していません |
| 既出局面、未見局面 | 盤面・持ち駒・手番がまったく同じ局面が学習集合にあった局面と、なかった局面。手数は区別しません |

## 指手の予測の指標

| 用語 | 意味 |
|---|---|
| パープレキシティ（PP） | 次の指手の当てにくさ。正解の指手に与えた確率の対数を平均し、符号を反転して指数に戻した値です。小さいほど良く、1に近いほど迷わず当てています |
| 指手top1 | ビーム探索で得た候補の第1位が、棋譜の指手と一致した割合 |
| 指手top5 | ビーム探索で得た5つの候補の中に、棋譜の指手が入っていた割合 |
| top1合法率 | ビーム探索で得た候補の第1位が、合法手だった割合。モデルには規則を与えていないので、盤面を追えているかの手がかりになります |
| Start課題 | 履歴の後に駒の種類のトークンを与え、その駒の移動元のマスを当てさせる課題。RAPなしのモデルにとっては学習中に見たことのない入力です |
| End課題 | 履歴の後に正しい移動元のトークン（成りなら成りのトークンまで）を与え、移動先のマスを当てさせる課題。条件の比較にはこちらを使います |
| Start_top1、End_top1 | それぞれの課題で、モデルの第1候補が実際のマスと一致した割合 |
| R精度 | 合法な答えがN個あるとき、モデルの上位N個の候補のうち合法なものの割合。Start_R精度、End_R精度の列があります |

## 局面の読み取り（プローブ）の指標

| 用語 | 意味 |
|---|---|
| 線形プローブ | モデル本体は変えずに、隠れ状態だけを入力にして盤面や持ち駒を当てる単純な分類器。当てられれば、その情報が隠れ状態から線形に読み出せると言えます |
| 選択層 | 検証集合でプローブの損失が最も小さかった層。評価集合で選ぶと値が実力より高く出るので、検証集合で選びます |
| 最終層 | モデルの最後の層（第12層） |
| F1 | 「当てたものがどれだけ正しいか」と「正解をどれだけ拾えたか」を合わせた成績。0から1の値です |
| macro-F1 | 種類ごとにF1を計算し、単純に平均した値。数の多い種類（空マスなど）に引っ張られにくくなります。評価集合に1件も出てこない種類は平均から除きます |
| 盤面macroF1 | 81マスそれぞれについて、空か、どちらのどの駒か（29種類）を当てた成績 |
| 持ち駒macroF1 | 先手・後手それぞれ7種類の持ち駒（計14項目）の枚数を当てた成績 |
| 局面完全一致 | 盤面81マス、持ち駒14項目、手番がすべて合っていた局面の割合 |
| 終端復号 | 棋譜の最後の局面と、その1手前の局面のどちらが最後かを、線形プローブで当てる課題 |

## 比較の下限

| 用語 | 意味 |
|---|---|
| ベースライン（下限） | 何も読み取らなくても届いてしまう水準。モデルの値は必ずこれと並べます |
| 多数派ベースライン | 学習集合で最も多かった答えを常に返した場合の成績。盤面なら、各マスで最も多かった種類を答えます |
| 暗記ベースライン | 評価の局面と同じ局面を学習集合から探し、そこで最も多く指された指手を答えた場合の成績。学習集合にない局面は不正解として数えます |
| 被覆率 | 評価の局面のうち、同じ局面が学習集合にあった割合 |
| 最頻手ベースライン | 局面を見ずに、学習集合全体で最も多い指手を常に答えた場合の成績 |
| エントロピー | どのくらい予測しにくいかを表す量（ビット）。1種類しか指されていなければ0、2種類が半々なら1です |

## 持ち駒への依存と介入

| 用語 | 意味 |
|---|---|
| 指手依存差（局面復号の指手依存性） | 同じ履歴に、駒打ちの最初のトークンを続けた場合と、通常の移動を続けた場合とで、プローブが正しい持ち駒の枚数に与える確率がどれだけ違うか。前者から後者を引いた値で、層6、9、12で測っています |
| 遮断（ablation） | 予測する位置から特定の過去の位置への注意にマスクをかけて、出力がどう変わるかを見る実験。止めるのは直接の経路だけで、別の位置を経由する経路は残ります。手順は例付きで[CSVの作られ方と、各列の計算内容](csv_computation.md)の3.6にあります |
| 注意マスク | 特定の位置への注意の割合を0にし、残りの割合を合計1に戻す操作。その位置からは直接に情報が届かなくなります |
| 関連履歴 | 持ち駒の枚数を変えた過去の指手の位置。遮断でマスクをかける対象です |
| 対照 | 比べるための基準となる条件。遮断では、持ち駒と関係のない過去の位置を、距離と数をそろえて同じだけマスクをかけます |
| コントラスト（contrast） | 関連履歴にマスクをかけたときの変化から、対照にマスクをかけたときの変化を引いた値。負なら、関連履歴にマスクをかけたほうが正解の確率が大きく下がったことを表します |
| 保有駒への確率（確率質量） | 駒打ちのトークンを与えた後、モデルが各駒の種類に与える確率のうち、実際に手元にある駒の種類の確率を足し合わせた値 |
| activation patching | 隠れ状態を別の入力のものに差し替えて、出力の変化を見る方法。遮断とは別物で、この研究では実施していません |

## 統計

| 用語 | 意味 |
|---|---|
| 標準偏差 | 値のばらつきの大きさ。この研究では3シードの値から標本標準偏差を計算しています |
| 信頼区間（CI） | 評価に使った対局を取り替えても、値が収まるだろう範囲の目安。列名に `_ci_lower`、`_ci_upper` が付きます。シード間のばらつき（学習の揺れ）とは別物で、評価データの揺れを表します |
| 対局単位ブートストラップ | 評価の対局を重複を許して選び直し、何度も計算し直して信頼区間を求める方法。同じ対局の局面はまとめて扱います。局面単位で行うと区間が狭く出ます |
| 交絡 | 2つの要因が同時に変わっているため、どちらが結果を生んだのか区別できない状態 |
| 母数 | 割合を計算するときの分母になる件数 |

## データの形式

| 用語 | 意味 |
|---|---|
| JSON | データを「名前：値」の組で入れ子にして保存する形式。Pythonでは辞書として読めます |
| 来歴（provenance） | そのファイルをどのプログラムの、どの版で作ったかの記録 |
| by_run.csv | 1行が1モデル、1列が1指標の表。全844指標が入っています |
