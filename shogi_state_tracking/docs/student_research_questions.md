# 実験結果から問いに答える：分析ガイド

> 用語の意味は[用語集](glossary.md)にまとめてあります。各用語は、この文書で最初に出てくる箇所から用語集へリンクしています。

この文書は、`student_data/` にある実験結果を使って、研究上の問いに部分的に答えるための手引きです。

先に次の2つを読んでください。

- [research_overview.md](research_overview.md)：研究の背景と実験の構成
- [student_analysis_guide.md](student_analysis_guide.md)：CSVの作り方と、書いてはいけないこと

ここに挙げる6つの問いは、**どれも今あるデータだけでは完全には答えられません。** 何が分かり、何が分からないかを自分で切り分けることが、この課題の中心です。

答えや数値はこの文書には書いていません。自分で計算して確かめてください。

## 1　データの場所

| 場所 | 中身 | 使い方 |

## 2　どの問いにも共通する考え方

分析の前に、次の4つを頭に入れてください。どの問いでもこれが判断の根拠になります。

### 2.1 比較の下限と並べる

**モデルの値を単独で見ても、良いのか悪いのか分かりません。** 何もしなくても届いてしまう値（下限）と比べて初めて意味を持ちます。

> **[多数派ベースライン](glossary.md)**：いつも一番多い答えを返した場合の成績。例えば盤面のマスは空マスが多いので、「全部空マス」と答えるだけでかなり当たります。モデルがこれを超えていなければ、盤面を読めているとは言えません。

> **[暗記ベースライン](glossary.md)**：評価する局面と同じ局面を学習データから探し、そこで最も多かった指手を答えた場合の成績。モデルがこれを超えた分が、丸暗記では説明できない部分です。

### 2.2 シード間のばらつきと比べる

> **シード**：学習を始めるときの乱数の初期値。同じ条件でも、シードが違えば結果が少し変わります。

条件の差が、シードを変えたときの揺れ（標準偏差）より小さければ、それは偶然の揺れかもしれません。3シードあるので、条件ごとに平均と標準偏差を出し、**差と標準偏差を並べて**書いてください。

> **標準偏差**：値のばらつきの大きさ。3つの値が近ければ小さく、散らばっていれば大きくなります。

> **[信頼区間](glossary.md)（CI）**：列名に `_ci_lower`、`_ci_upper` が付いているもの。評価に使った対局を取り替えても、値がこの範囲に収まるだろうという目安です。シード間のばらつきとは別物です。前者は評価データの揺れ、後者は学習の揺れを表します。

### 2.3 交絡に気をつける

> **[交絡](glossary.md)**：2つの要因が同時に変わっているため、どちらが結果を生んだのか区別できない状態。

例えば、対局の終盤ほど「[駒打ち](glossary.md)」という難しい種類の指手が増えます。終盤で成績が落ちたとき、それが「終盤だから」なのか「駒打ちが増えたから」なのかは、そのままでは分かりません。**一方を固定して、もう一方だけを動かす**ことで切り分けます。

### 2.4 母数をそろえる

> **[母数](glossary.md)**：割合を計算するときの分母になる件数。

2つの割合を比べるときは、同じ集団について計算した値かを確かめてください。「全局面での正解率」と「学習で見ていない局面だけでの正解率」は、分母が違うので直接は比べられません。

## 3　Pythonのヒント

使うモジュールと、主な使いどころだけを示します。組み立ては自分で考えてください。

### pandas（表を扱う）

```python
import pandas as pd
df = pd.read_csv("student_data/summary/by_run.csv")
```

- `df.columns` で列名の一覧が見られます。844列あるので、`[c for c in df.columns if c.startswith("fh_")]` のように絞り込むと探しやすくなります
- `df["condition"]` で条件名の列、`df["seed"]` でシードの列が取れます
- `df.groupby("condition")[列名]` で条件ごとにまとめられます。その後に `.mean()`、`.std()`、`.agg(["mean", "std"])` を付けると平均や標準偏差が出ます
- `df[df["condition"] == "vanilla-p0.0"]` で特定の条件の行だけを取り出せます
- 学生用の `summary.csv` などは先頭にBOM（Excel用の印）が付いています。列名がおかしいときは `encoding="utf-8-sig"` を指定してください。`by_run.csv` には付いていません

### json と pathlib（元のJSONを読む）

```python
import json
from pathlib import Path
root = Path("student_data/.extracted/analysis_bundle/results/llama-reference/implicit-initial")
```

- `root.glob("*/seed-*/evaluation/<ファイル名>")` で12モデル分のファイルを一度に列挙できます
- `json.loads(path.read_text())` で辞書として読めます
- 辞書の中身が分からないときは `list(d.keys())` で1階層ずつ確かめてください。いきなり深いところを指定すると `KeyError` になります
- パスから条件名とシードを取り出すには `path.parts` が使えます

### matplotlib（図を描く）

```python
import matplotlib.pyplot as plt
```

- 手数による変化を見るなら `plt.plot` で折れ線、条件の比較なら `plt.bar` で棒グラフ
- 平均と標準偏差を同時に描くには `plt.errorbar` の `yerr` 引数
- **3シードの値は平均だけにせず、点や誤差棒で示してください。** ばらつきが見えない図は判断を誤らせます

## 4　問い

各問いは同じ形で書いてあります。

- **何を問うか**
- **なぜ大事か**
- **使うデータ**
- **分析の手順**（ヒント）
- **部分的に分かること**
- **分からないこと**（今のデータでは答えられない部分）

「分からないこと」も必ず自分の言葉でまとめてください。それを書けることが、結果を正しく理解している証拠になります。

### 問い1　盤面や持ち駒の情報は、モデルの中に保持され続けているのか、それとも必要なときにその場で作られるのか

#### 何を問うか

モデルが盤面や[持ち駒](glossary.md)を「メモのように書き留めて持ち続けている」のか、「聞かれるたびに過去の指手を見返して組み立てている」のか、という問いです。

#### なぜ大事か

前者なら、モデルの中に局面の記録があることになります。後者なら、局面はそのたびに計算されるもので、記録としては存在しません。「モデルが盤面を持っている」と言えるかどうかが、この区別にかかっています。

#### 使うデータ

`by_run.csv` の次の列です。

| 列 | 意味 |
|---|---|
| `action_difference_l6`、`_l9`、`_l12` | [指手依存差](glossary.md)。同じ履歴から「駒打ち」に進んだ場合と「通常の移動」に進んだ場合で、持ち駒の読み取りやすさがどれだけ違うか。数字は層の番号 |
| `action_difference_l*_ci_lower`、`_ci_upper` | その信頼区間 |
| `ablation_{middle,late,all}_relevant_delta` | 持ち駒を変えた過去の指手への注意にマスクをかけたときの変化 |
| `ablation_{middle,late,all}_matched_control_delta` | 無関係な位置に同じ数だけマスクをかけたときの変化（[対照](glossary.md)） |

> **層**：モデルは12段の計算を順に重ねています。その1段を層と呼びます。数字が大きいほど出力に近い段です。

> **注意（attention）**：モデルが、過去のどの位置の情報を参照するかを決める仕組み。

> **[遮断](glossary.md)（ablation）**：予測する位置から特定の過去の位置への注意にマスクをかけ、出力がどう変わるかを見る実験。`middle` は入力側から7番目の層だけ、`late` は10番目の層だけ、`all` は12層すべてでマスクをかけたものです。手順は例付きで[CSVの作られ方と、各列の計算内容](csv_computation.md)の3.6にあります。

> **対照**：比べるための基準となる条件。「マスクをかけること自体」の影響を差し引くために、関係のない位置に同じ数だけマスクをかけた場合と比べます。

#### 分析の手順

1. 指手依存差が0から離れているかを確かめる。信頼区間が0をまたいでいなければ、差があると言える
2. 層6、9、12で指手依存差がどう変わるかを並べる
3. 遮断について、`relevant_delta` と `matched_control_delta` を並べ、差が大きいかを見る
4. `middle`、`late`、`all` のどれで大きく変わるかを比べる
5. 以上を、[主3条件](glossary.md)（RAPなし、q=0.15、q=0.25）それぞれ3シードで確かめる

**なぜそうするか**：保持され続けているだけなら、次に何の指手が来るかで読み取りやすさは変わらないはずです（手順1）。また、1つの層だけが情報を担っているなら、その層でマスクをかけたときだけ大きく変わるはずです（手順4）。

#### 部分的に分かること

指手依存差が0でなければ、「問われ方によって読み取りやすさが変わる」、つまりその場で形成される側面があることまでは言えます。遮断の結果からは、情報を担っているのが1つの層なのか、複数の層にまたがるのかが分かります。

#### 分からないこと

**完全に「その場で作られる」とも言えません。** 保持と形成が混ざっている可能性を、このデータでは否定できません。

区別するには、次の指手に関係のない持ち駒も同じくらい読めるかを調べる必要があります。保持されているなら関係の有無で差は出ず、その場で作られているなら関係するものだけが読めるはずです。この集計は今のデータにはありません。

#### 注意

手数（何手目か）で読み取りやすさを比べたくなりますが、**この問いには使えません。** 序盤は持ち駒がほぼ空で、当てるのが簡単です。手数が増えると追うべき情報そのものが増えます。精度の低下が「保持が崩れた」のか「課題が難しくなった」のかを区別できません（2.3の交絡）。

### 問い2　対局が進むと指手の予測が難しくなるのは、局面を追えなくなるからか、それとも指手の種類が変わるからか

#### 何を問うか

対局の後半ほど、モデルの指手の予測は当たりにくくなります。その理由が「局面を追い続けるのが難しくなる」ことなのか、「後半は難しい種類の指手が増える」ことなのかを問います。

#### なぜ大事か

前者なら、モデルが局面を追い続ける力に限界があることになります。後者なら、モデルの能力は変わっておらず、終盤に駒打ちが増えて課題の中身が変わっただけです。同じ「成績が落ちた」でも、意味がまったく違います。

#### 使うデータ

評価集合の全指手（約72万手）を対象にした評価です。

| 場所 | 列・キー | 意味 |
|---|---|---|
| `by_run.csv` | `fh_move_perplexity_ply_*` | 手数の範囲ごとの指手[パープレキシティ](glossary.md) |
| 同上 | `fh_destination_given_source_top1_ply_*` | 手数の範囲ごとの、移動元を与えたときの移動先の正解率 |
| 同上 | `fh_drop_move_rate_ply_*` | 手数の範囲ごとの、駒打ちの割合 |
| 同上 | `fh_*_kind_drop`、`_kind_normal`、`_kind_promotion` | 指手の種類ごとの値 |
| 元のJSON | `full_history_move_metrics.json` の `metrics` 以下、`ply_33_64__normal` のようなキー | 手数×種類の組み合わせ。CSVには入っていない |

手数の範囲は `ply_1_8`（1〜8手目）、`ply_9_16`、`ply_17_32`、`ply_33_64`、`ply_65_128`、`ply_129_plus`（129手目以降）です。`ply_0` は初手で、全対局で同じ局面なので別扱いにしてください。

> **パープレキシティ（PP）**：次の指手の「当てにくさ」。小さいほど良い。1に近いほど迷わず当てています。

> **駒打ち**：持ち駒を盤に置く指手。将棋にしかない操作です。

> **[教師強制](glossary.md)**：正解の途中までをモデルに与えて、次の1[トークン](glossary.md)だけを当てさせる評価の方法。`fh_` の付く列はすべてこの方法です。

#### 分析の手順

1. 手数の範囲ごとに、PPと移動先の正解率を並べる。後半ほど悪くなるかを見る
2. 同じく駒打ちの割合を並べる。後半ほど増えるかを見る
3. 元のJSONから、通常の移動（`__normal`）だけを手数ごとに取り出す
4. 通常の移動だけに限っても、手数とともに成績が落ちるかを見る
5. 全体の低下と、通常の移動だけの低下を比べる

**なぜそうするか**：手順3〜4が要です。指手の種類を1つに固定すれば、「種類が変わったから」という説明は使えなくなります（2.3の交絡の切り分け）。それでも落ちるなら、種類の変化だけでは説明できません。

#### 部分的に分かること

種類を固定しても成績が落ちるかどうかで、**「種類の変化だけが原因ではない」かどうか**が分かります。全体の低下と通常の移動だけの低下を比べれば、種類の変化がどのくらい寄与しているかの見当もつきます。

#### 分からないこと

通常の移動だけに限っても成績が落ちたとして、それが局面を追えなくなったからなのか、終盤の局面そのものが難しいからなのかは区別できません。終盤は駒がぶつかり合い、指せる手（[合法手](glossary.md)）の数が変わります。候補が多ければ、局面を正しく追えていても当てにくくなります。

これを分けるには、合法手の数をそろえて比べる集計が必要ですが、全指手の評価にはありません。

#### 注意

`fh_source_top1_kind_drop` は「移動元の正解率」ではありません。駒打ちの最初のトークンは移動元のマスではなく `<DROP>` なので、この値は「駒打ちが来ることを当てたか」を表します。通常の移動の `source_top1`（どのマスの駒を動かすか）と並べて比べてはいけません。

### 問い3　駒打ちで打つ駒の種類を当てられなくなるのは、持ち駒を把握できていないからか、どれを打つか選ぶのが難しいからか

#### 何を問うか

駒打ちのとき、モデルが「どの駒を打つか」を当てられる割合は、対局が進むと変わります。その理由が「手元に何があるか分かっていない」ことなのか、「手元の駒は分かっているが、どれを打つか選ぶのが難しい」ことなのかを問います。

#### なぜ大事か

持ち駒は盤の上に見えません。過去に取った駒と打った駒をたどらないと分からない情報です。前者なら持ち駒の追跡に失敗しており、後者なら追跡はできていて判断が難しいだけです。この研究が将棋を選んだ理由（持ち駒）に直接かかわる問いです。

#### 使うデータ

| 列 | 意味 |
|---|---|
| `fh_drop_piece_top1_ply_*` | 手数の範囲ごとの、打つ駒の種類の正解率 |
| `fh_drop_piece_top1_kind_drop` | 駒打ち全体での同じ値 |
| `handdrop_mean_probability_mass_on_held_pieces_given_drop` | 駒打ちを指示したとき、実際に手元にある駒に与えた確率の合計 |
| `hand_drop_changed_slot_delta_accuracy` など `hand_drop_*` | 駒打ちの前後で持ち駒の変化を読み取れたか |

> **確率の合計（確率質量）**：モデルは「この駒を打つ確率は何％」という形で答えを出します。手元にある駒の確率を足し合わせたものです。1に近いほど、持っていない駒を打とうとしていないことになります。

#### 分析の手順

1. 打つ駒の正解率が、手数とともにどう変わるかを並べる
2. 手元の駒への確率の合計を見る
3. 2つを比べ、「正解の駒は外すが、持っている駒の中からは選んでいる」状態かどうかを考える

**なぜそうするか**：打つ駒の正解率は、「持っている駒を知っている」ことと「棋譜と同じ駒を選べた」ことの両方が必要です。一方、手元の駒への確率の合計は、前者だけを測ります。2つを比べれば、どちらが原因かの手がかりになります。

#### 部分的に分かること

手元の駒への確率の合計が高ければ、少なくとも全体としては持ち駒を把握できていると考えられます。そのうえで打つ駒の正解率が低ければ、選択の難しさが原因である可能性が高まります。

#### 分からないこと

**手元の駒への確率の合計は、全体の値しかありません。** 手数ごとには分かれていないので、「後半で把握に失敗し始めるのか」は確かめられません。

また、後半ほど持っている駒の種類が増えます。3種類持っていれば、でたらめに選んでも3回に1回は当たります。持っている駒の種類数を下限として並べる必要がありますが、その集計もありません。

#### 注意

序盤の駒打ちは件数が非常に少ないことがあります。元のJSONの `drop_piece_examples` で件数を確かめてから解釈してください。件数が少ない範囲の割合は、たまたまの影響を強く受けます。

### 問い4　学習で見たことのない局面でも、指手を予測できるか

#### 何を問うか

評価に使った局面の中には、学習データにまったく同じ局面が含まれていたもの（[既出局面](glossary.md)）と、含まれていなかったもの（[未見局面](glossary.md)）があります。未見局面でもモデルが通用するかを問います。

#### なぜ大事か

既出局面なら、丸暗記でも当てられます。未見局面でも当てられて初めて、モデルが局面から判断している可能性が出てきます。また、チェスの先行研究の値と比べるときも、丸暗記の効かない未見局面のほうが条件が近くなります。

#### 使うデータ

| 列 | 意味 |
|---|---|
| `move_perplexity_unseen_position` | 未見局面での指手パープレキシティ |
| `move_perplexity` | 既出と未見を合わせた値 |
| `move_top1_unseen_position` | 未見局面でのtop1 |
| `baseline_train_position_coverage` | 評価局面のうち、学習データにも出てきた割合 |
| `lishogi_move_*_unseen_position` | 別のサイト（[Lishogi](glossary.md)）の棋譜での同じ値 |
| 元のJSON `probes/probe_metrics.json` の `evaluation_by_position_scope` | 盤面の読み取りの、既出／未見別の値。`seen_position`、`unseen_position` のキーがある |

> **top1**：モデルが一番確率が高いと答えた指手が、棋譜の指手と一致した割合。

#### 分析の手順

1. 未見局面と、既出・未見を合わせた値を並べる
2. 学習データにも出てきた局面がどのくらいあるかを確かめる
3. 盤面の読み取り（プローブ）についても、既出と未見で比べる
4. 条件（RAPの有無）で、未見局面での値に差があるかを、シード間の標準偏差と比べる

**なぜそうするか**：合わせた値は、既出局面の割合が高いほど丸暗記に助けられます（手順2）。未見局面だけを取り出せば、その影響を外せます。

#### 部分的に分かること

未見局面で成績がどのくらい下がるか、つまり合わせた値がどのくらい丸暗記に助けられていたかが分かります。盤面の読み取りが未見局面でも保たれているかも分かります。

#### 分からないこと

**既出／未見の分割は、8手目と32手目の2点だけを抜き出した評価にしかありません。** 全指手の評価（問い2のデータ）では分けていないので、対局全体について未見局面での値は分かりません。

また、未見局面といっても、人間の棋譜やコンピュータの棋譜から来た「ありそうな」局面です。でたらめな合法手を重ねて作った局面でどうなるかは調べていません。

#### 注意

チェスの先行研究の値と比べるときは、棋譜も[語彙](glossary.md)もモデルも違います。数値を並べて「将棋のほうが易しい」などとは書けません。比べるなら、どの条件が近く、どの条件が違うかを必ず添えてください。

### 問い5　指手の予測のうち、丸暗記で説明できるのはどこまでか

#### 何を問うか

モデルが指手を当てるとき、その成績のうちどれだけが「学習データで同じ局面を見たことがあるから」で説明できるのかを問います。

#### なぜ大事か

この研究は、「指手を当てられても、盤面を追えている証拠にはならない」ところから出発しています。丸暗記で届く水準を示し、それを超えているかを確かめることで、この問いに一歩近づけます。

#### 使うデータ

| 場所 | 列 | 意味 |
|---|---|---|
| `baselines.csv` または `by_run.csv` | `baseline_train_position_top1` | 暗記ベースラインのtop1 |
| 同上 | `baseline_train_position_coverage` | 評価局面のうち学習データにもあった割合 |
| 同上 | `baseline_global_move_top1` | 局面を見ずに、学習データで最も多い指手を常に答えた場合 |
| 同上 | `baseline_mean_distinct_next_moves` | 同じ局面から何種類の指手が指されていたか |
| `by_run.csv` | `move_top1` | モデルのtop1 |
| 同上 | `move_top1_unseen_position` | 未見局面でのモデルのtop1 |

`baseline_` の付く値はモデルではなくデータから計算した値で、12モデルすべてで同じになります。条件の比較の表に行として入れず、表の下に下限として添えてください。

#### 分析の手順

1. 3つの下限（局面を見ない場合、丸暗記の場合）とモデルの値を並べる
2. 丸暗記がどこまで届くかを、学習データにも出てきた局面の割合と合わせて読む
3. 同じ局面から指された指手の種類数を見て、棋譜の手がどのくらい決まっているかを考える

**なぜそうするか**：局面を見ない下限は「何も考えない」水準、丸暗記の下限は「覚えているだけ」の水準です。モデルの値がその間のどこにあるかで、丸暗記を超えた部分の大きさが分かります。

#### 部分的に分かること

モデルの成績が丸暗記の水準を超えているか、超えているならどのくらいかが分かります。

#### 分からないこと

**未見局面での比較ができません。** 暗記ベースラインは、学習データにない局面では答えを持たないので、未見局面での値は意味を持ちません。そのため、「未見局面でモデルがどれだけ丸暗記を超えているか」を同じ物差しで測れません。

`move_top1`（8手目・32手目のみ）と、暗記ベースライン（同じ局面が対象）は母数がそろっていますが、`move_top1_unseen_position` と暗記ベースラインは母数が違うので、直接並べないでください（2.4）。

#### 注意

このデータの棋譜はコンピュータ同士の対局です。コンピュータは指し方が偏るので、同じ局面からの指手の種類が少なく、丸暗記が効きやすくなっています。人間の棋譜で同じことが言えるとは限りません。

### 問い6　駒打ちの判断に、過去の駒打ちに関係する指手を実際に使っているか

#### 何を問うか

モデルが駒打ちを判断するとき、過去の「駒を取った手」「駒を打った手」の情報を、注意を通じて実際に参照しているかを問います。

#### なぜ大事か

「盤面や持ち駒を読み取れる」ことと、「それを使って指手を決めている」ことは別です。読み取れても使っていないかもしれません。注意にマスクをかけて出力が変われば、少なくともその経路を使っている証拠になります。

#### 使うデータ

`by_run.csv` の `droprel_ablation_` で始まる列です（主3条件のみ。APにはありません）。

| 列 | 意味 |
|---|---|
| `droprel_ablation_{middle,late,all}_relevant_delta` | 駒打ちに関係する過去の指手への注意にマスクをかけたときの変化 |
| `droprel_ablation_{middle,late,all}_matched_control_delta` | 無関係な位置に同じ数だけマスクをかけたときの変化 |
| `droprel_ablation_{middle,late,all}_contrast_mean` | 上の2つの差 |
| `droprel_ablation_{middle,late,all}_contrast_ci_lower`、`_ci_upper` | その信頼区間 |
| `droprel_split_passed` | 分析用と調整用の対局が重なっていないことの確認。`True` であること |

APに無いのは設計によるものです。APは過去の指手にも正解の駒の種類を付けて学習しているため、この実験の意味が他の条件と変わってしまいます。

#### 分析の手順

1. `droprel_split_passed` がすべて `True` であることを確かめる
2. 関係する位置にマスクをかけた場合と、無関係な位置にマスクをかけた場合を並べる
3. 差の信頼区間が0をまたいでいないかを見る
4. `middle`、`late`、`all` で比べる
5. 主3条件それぞれ3シードで確かめる

**なぜそうするか**：関係する位置にだけマスクをかけたときに大きく変わり、無関係な位置では変わらないなら、モデルは関係する指手を選んで参照していることになります（2.3の対照の考え方）。手順1は、実験が公正に行われたことの確認です。

#### 部分的に分かること

関係する過去の指手への注意が、駒打ちの判断に寄与しているかどうかが分かります。

#### 分からないこと

**マスクで止めたのは「直接の注意」だけです。** モデルの中では、ある位置の情報が別の位置を経由して間接的に伝わることがあります。その経路は残っているので、「この情報がないと駒打ちできない」とまでは言えません。

また、特定の[注意ヘッド](glossary.md)（注意の仕組みの中の小さな部品）が持ち駒を覚えている、とも言えません。

## 6　まとめるときに

- **表を先に作ってから文章を書いてください。** 文章を先に書くと、それに合う数値を探してしまいます
- どの問いでも、「部分的に分かること」と「分からないこと」を分けて書いてください
- 条件の差は、必ずシード間の標準偏差と並べてください
- モデルの値は、必ず下限と並べてください
- 「モデルが盤面を理解している」「強い」とは書けません。理由は [student_analysis_guide.md](student_analysis_guide.md) の「書けないこと」にあります

分からないことを正直に書くのは、研究として欠点ではありません。**何が分かっていないかを正確に示せること自体が、結果を読めていることの証拠**です。
